> Dong, J. et al. (2025). *Behavior-Equivalent Token: Single-Token Replacement for Long Prompts in LLMs*. arXiv:2511.23271.
{: .prompt-info }

## Motivation

ICAE 논문에서 4배 이상 토큰을 압축할 경우 원문 복원 능력이 떨어진다는 결과가 있었다. 하지만 이 논문에서는 system prompt를 하나의 BE 토큰으로 압축시키는 내용을 담고 있다. 3000토큰을 하나의 토큰으로 압축시켰을 때 가장 성능이 좋아지는 지점이 나타난다는 내용이 있어서 읽게 되었다.

## Summary

### Core Idea

정교하게 설계된 LLM의 System prompt는 상당한 길이로 인해 추론 지연 시간 증가, 높은 계산 비용, 유효 컨텍스트 길이 감소와 같은 단점이 발생한다. 이를 해결하기 위해 하나의 토큰에 시스템 프롬프트를 압축해서 사용하면 기존 성능을 유지하면서 시스템 프롬프트의 길이는 줄일 수 있지 않을까?

### Method

![기존 압축 방법론과 논문에서 제시하는 압축 방법의 비교 도식](</assets/img/2026-08-03-논문리뷰(2)/01.png>)
_(a), (b)는 기존 압축 방법론이고 (c) ~ (f)가 논문에서 제시하는 압축 방법이다._

![Stage 0에서 [AE] 토큰을 복원 트리거로 학습시키는 과정](</assets/img/2026-08-03-논문리뷰(2)/02.png>)
_Stage 0: [AE] 토큰 사전학습_

**Stage 0** : Sequence + [AE]를 LLM 입력으로 넣어서 Sequence가 나오도록 [AE]를 학습시킨다. 여기서 [AE]는 복원 작업에 대한 트리거 역할을 하도록 만들어진다. 이는 다음 단계에서 [BE] 토큰이 정보를 인코딩하도록 도와준다.

![Stage 1에서 [AE]를 활용해 [BE] 토큰을 학습시키는 과정](</assets/img/2026-08-03-논문리뷰(2)/03.png>)
_Stage 1: [BE] 토큰으로의 정보 압축_

**Stage 1** : [AE]를 활용해서 [BE]를 학습시킨다. 원래 프롬프트의 텍스트 정보를 [BE]로 압축하기 위해 [[BE], [AE]]에 조건화되었을 때 P를 재구성하도록 모델을 학습시킨다. 이 때 [AE]와 모델 파라미터는 고정된다. 여기서 손실을 최소화하면 [BE] 토큰이 P를 재생성하는 데 필요한 모든 정보를 인코딩하도록 강제된다.

![지식 증류 손실 함수 수식](</assets/img/2026-08-03-논문리뷰(2)/04.png>)
_지식 증류에 대한 손실 함수 식. λ는 손실 가중치로 복원과 지식 증류의 비중을 조절한다._

![Stage 2에서 지식 증류로 logits를 정렬시키는 과정](</assets/img/2026-08-03-논문리뷰(2)/05.png>)
_Stage 2: 행동 등가성 확보를 위한 지식 증류_

**Stage 2** : P를 [BE]로 대체해도 하류 쿼리에 대해 동일한 조건부 출력 분포가 생성되도록 보장하기 위해 지식 증류를 사용한다. system prompt를 BE로 대체했을 때 logits가 서로 같도록 [BE]를 학습시킨다.

- Stage 1에서는 복원 작업만 이루어졌다면, Stage 2에서는 실제 정보를 인코딩했는지를 학습한다.

이러한 단일 토큰 대체 방식은 사용자 상호작용 및 모델 생성을 위해 컨텍스트 윈도우의 거의 전체를 확보하며, 원래 프롬프트가 지시하는 동작을 유지하면서 지연 시간을 획기적으로 줄여준다.

### Experiments & Results

- **데이터셋** : RoleLLM, GSM8K, HPD를 포함한 여러 데이터를 사용
- **평가 지표** : GPT 기반 상대평가, RoleLLM 벤치마크의 참조 응답 비교, GSM8K 정확도, HPD 서사 연속성에 대한 perplexity를 사용
- **백본 모델** : Llama-3.2-1B-Instruct, Llama-3.2-3B-Instruct, Llama-3.1-8B-Instruct, Qwen3-4B-Instruct-2507
- **베이스라인** : 기존 System prompt 사용, System prompt 미사용, Memory token, Soft Prompts, PCC

#### 추가

1. 압축의 목표를 정보 보존이 아니라 행동 보존으로 넘어가면 한계가 크게 달라질 것이다.
2. 이 논문에서는 하나의 대화만 가지고 평가했다. 대화가 길어질수록 [BE] 토큰의 내용이 희석될 수 있다.
3. 여러 [BE] 토큰을 조합하는 방식은 향후 과제로 남겨둔다.

## Personal Notes

### memory slots와 [BE]의 차이

ICAE 논문의 memory slots와 BE 토큰과는 차이가 있다. ICAE는 인코더의 역할로 사용자의 입력에 따라서 바로 압축해서 사용할 수 있게 만드는 압축기이다. 그 과정에서 만들어진 압축 토큰들을 memory slots라고 한다. 매 입력마다 값이 달라지므로 범용성이 중요하다. BE 토큰은 학습을 통해 만들어지는 하나의 압축 토큰으로, memory slots보다 훨씬 많은 토큰을 압축시킬 수 있다.

### ICAE 논문의 [AE]와 여기서의 [AE] 비교

이 논문에서는 기존의 [AE]와는 달리 범용적이고 독립적인 메커니즘이라고 설명한다.

두 논문의 [AE] 모두 복원 작업의 트리거 역할을 하는 것은 동일하다. 하지만 학습 방법이 다르다. 여기서의 [AE]는 따로 사전학습을 통해 만들어진다. 하지만 ICAE에서의 [AE]는 ICAE 안에서 메모리 토큰과 함께 학습되기 때문에 ICAE 밖으로 나가면 그 의미를 잃게 된다.

### 이론적 토큰 압축의 한계

이 논문에서는 토큰 압축의 최적점을 3000배로 잡았다. 하지만 수학 이론적으로는 4096차원이라고 가정했을 때 $$(2^{16})^{4096} = 2^{65536}$$ 로 무한에 가까운 정보를 압축할 수 있다. 하지만 이러한 결과가 나온 이유는 현재의 모델로는 4096차원의 임베딩 벡터를 한 번에 읽어내지 못하기 때문이라고 추측해본다.
