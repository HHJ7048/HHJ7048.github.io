## Motivation

Guardrail Model 들에 대해서 알아보려고 읽어보았다. 기존 Llama Guard와 비교하면서 kNN Guard라는 모델이 활성화 값을 이용해서 기존 Text 기반 분류 모델인 Llama Guard의 취약점을 해결한다는 내용을 보게 되었고, kNN Guard에 대한 논문을 읽어보는 계기가 되었다.

Llama Guard의 문제점을 얼마나 해결했는지에 초점을 맞춰서 읽어보았다.

## Summary

### Architecture

![kNN Guard 전체 아키텍처 — Phase 1 뱅크 구축과 Phase 2 추론 흐름](</assets/img/2026-08-21-논문리뷰(4)/01.png>)

#### PHASE 1

Bank Building 단계는 ALLOW / BLOCK 판단을 위한 비교 데이터를 cache 시키는 작업이다.

- Frozen LLM Model의 여러 레이어의 활성화 값을 추출해서 Label과 함께 BANK를 구축한다.
- MiniLM에도 통과시켜 Embedding BANK를 동일하게 만들어낸다.
  - Score 1, Score 2를 계산하는 과정에서 사용된다.

이때 레이어별 가중치도 함께 확정된다. 클래스 간 거리를 클래스 내 분산으로 나눈 Fisher score로, 값이 클수록 safe/unsafe를 잘 가르는 레이어다.

$$ J_\ell = \frac{B_\ell}{W_\ell}, \qquad \alpha_\ell = \frac{\exp(J_\ell)}{\sum_{j \in L} \exp(J_j)} $$

#### PHASE 2

kNN Guard를 이용한 추론 과정이다. Score 1(활성화)과 Score 2(임베딩)을 계산한 다음, 두 지표를 이용해서 결론적으로 BLOCK / ALLOW를 판단한다.

**Score 1** : Prompt의 입력이 끝난 Frozen LLM 모델에서 Layer 별로 활성화 값을 뽑아낸다. 그리고 뽑아낸 활성화 값을 먼저 Fisher score 방식을 이용해서 가중치를 준다. 그런 다음 concat해서 BANK와 코사인 유사도를 구한다.

$$ \phi_{act}(\tilde{x}) = \bigoplus_{\ell \in L} \alpha_\ell \cdot \mathrm{norm}(h^{(\ell)}(\tilde{x})) $$

가장 feature들과 가까운 Label 13개를 뽑아낸 다음 그 비율을 Score 1으로 사용한다.

$$ s_{act}(x) = \frac{1}{k}\sum_{i \in N_k(x)} y_i $$

**Score 2** : Prompt를 MiniLM에 입력한다. 그렇게 나온 문장 임베딩 값을 위와 같은 방식으로 13개 뽑아낸다. 그 비율을 Score 2로 정의한다. (논문 그림 오류)

$$ \phi_{emb}(\tilde{x}) = \mathrm{norm}(E(\tilde{x})) $$

이렇게 구해진 두 Score를 단순 합산하는 것이 아니라, 얼마나 더 확신을 가지는지에 대한 지표로 변환한다.

$$ c_{act}(x) = \lvert s_{act}(x) - \tau \rvert, \quad c_{emb}(x) = \lvert s_{emb}(x) - \tau \rvert $$

![확신도(confidence) 차이에 따른 Score 융합 분기 로직](</assets/img/2026-08-21-논문리뷰(4)/02.png>)

$\gamma = 0.1$ 기준으로 분기한다.

- **$\Delta > \gamma$ → Winner-takes-all.** 더 확신하는 쪽 score를 그대로 채택하고, 다른 쪽은 버린다.
- **$\Delta \le \gamma$ → 확신도 가중 평균.** 아래 식으로 계산한다.

$$ s_{FE}(x) = \frac{c_{act}(x) \cdot s_{act}(x) + c_{emb}(x) \cdot s_{emb}(x)}{c_{act}(x) + c_{emb}(x)} $$

- **둘 다 정확히 0.5라 분모가 0이면 → 단순 평균** (코드상 예외처리 되어있다.)

최종적으로 이렇게 구해진 $s_{FE}(x)$ 를 이용해서 $s_{FE}(x) \ge \tau$ 이면 BLOCK, 아니면 ALLOW로 판단한다.

### 실험 & 결과

![Llama kNN Guard와 기존 Guard 모델의 F1 / FPR / 추론 시간 비교 표](</assets/img/2026-08-21-논문리뷰(4)/03.png>)

해석 : Llama kNNGuard가 준수한 F1 수치를 보여준다.

- System Prompt가 FPR을 효과적으로 낮춰 준다. (Sys Prompt가 없으면 오탐이 심해짐을 알 수 있다.)

기본 가이드라인이 모델 동작에 큰 도움을 주는 것을 확인할 수 있다.

추론 시간도 46.8ms로 기존 Llama Guard 보다 2배 정도 빠른 것을 확인할 수 있다.

![Safety / Jailbreak / Prompt Injection 도메인별 평가 결과](</assets/img/2026-08-21-논문리뷰(4)/04.png>)

해석

- **Safety** : ASR 14.3으로 양호하나 FPR 34.6으로 높게 측정됨
- **Jailbreak** : 세 도메인 중 가장 고르게 준수한 성능
- **Prompt Injection** : 나쁘지 않은 성능

Prompt Guard 2와 비교 시 공격은 더 잘 막지만 오탐이 많은 것을 확인할 수 있다.

![파인튜닝 방식 대비 kNN Guard의 구축(셋업) 시간 비교](</assets/img/2026-08-21-논문리뷰(4)/05.png>)

해석 : 기존 Fine-tuning 시키는 방식의 훈련보다는 kNNGuard가 압도적으로 빠르게 구축할 수 있음을 보여준다.

추가적으로 kNNGuard는 BANK samples을 50 → 1000개로 늘렸지만 성능 차이가 나지 않는다고 논문에서는 주장하고 있다. (따로 지표가 없음)

### 장점

- 파인튜닝 없이 guardrail 구축 — Llama Guard와 달리 학습 불필요
- 도메인 적응이 뱅크 교체로 완료 — 50~250개 뱅크만으로 도메인 특화 판정
- 학습 분포에 경계가 묶이지 않음 — 파인튜닝 분류기는 결정 경계가 학습 데이터에 고정
- 낮은 지연 — Nemotron Topic Guard V1의 2.7배, Safety Guard V2의 10배 빠름
- 해석 가능성 — 논문에 명시되진 않으나, 어떤 뱅크 프롬프트에서 오류가 났는지 해석 가능

### 한계점

- **완벽한 성능을 기대하기 어렵고 오탐률이 높게 나옴**
- **뱅크를 통한 단순 분류인 만큼, 뱅크가 유출될 경우 우회가 가능해짐**
- **시스템 프롬프트에 어느 정도 의존해야 함**

## Personal Notes

### 현재 진행중인 연구에 kNN Guard 적용

진행중인 공격 방식으로는 kNN Guard는 뚫을 수 없다.

### Llama Guard

![Llama Guard의 동작 구조 — LLM 입·출력단에 붙는 텍스트 분류 모델](</assets/img/2026-08-21-논문리뷰(4)/06.png>)

Llama Guard는 Llama 모델을 베이스로 파인튜닝 시킨 텍스트 분류 모델이다.

LLM 앞, 뒤에 붙어서 unsafe, harmful, refusal한 Text를 걸러준다.

#### 단점

- **텍스트 표면에서 동작하여 표면 조작에 취약**
  - 섭동·인코딩·암호화·토크나이저 조작 가능
- **능력 비대칭에 취약**
  - 가드가 막지 못하는 요청은 그대로 통과
- **타깃의 내부 상태가 아니라 텍스트만 봄**
  - 활성화 값을 반영하지 못함
- **생성형 분류라 무겁고 느림 (속도 측면)**
  - 모델 구축 시 파인튜닝 작업이 필요함
