## 어셈블리어

컴퓨터 기계어와 치환되는 언어로, 대표적으로 Intel 문법(NASM에서 사용)과 AT&T 문법(GAS에서 사용)이 있다.

### x86-64 어셈블리어 구조

![x86-64 어셈블리어 명령문의 기본 구조](</assets/img/2026-08-05-Xpert(6)/01.png>)
_어셈블리 명령문은 명령어와 피연산자로 구성된다_

어셈블리어는 `명령어, 피연산자, 연산의 입력 값` 으로 구성된다.

### 명령어

| 분류 | 명령 코드 |
| --- | --- |
| 데이터 이동 (Data Transfer) | `mov`, `lea` |
| 산술 연산 (Arithmetic) | `inc`, `dec`, `add`, `sub` |
| 논리 연산 (Logical) | `and`, `or`, `xor`, `not` |
| 비교 (Comparison) | `cmp`, `test` |
| 분기 (Branch) | `jmp`, `je`, `jg` |
| 스택 (Stack) | `push`, `pop` |
| 프로시져 (Procedure) | `call`, `ret`, `leave` |
| 시스템 콜 (System call) | `syscall` |

인텔의 x64에서 사용되는 중요한 21개의 명령어이다.

### 피연산자

- **상수** : 코드에 직접 들어있는 상수
- **레지스터** : CPU 내부의 저장 공간
- **메모리** : 주소에 담겨있는 값

#### 피연산자 표기법

![피연산자 표기법 정리](</assets/img/2026-08-05-Xpert(6)/02.png>)
_상수, 레지스터, 메모리 피연산자의 표기 방식_

#### 크기 지정자

- `BYTE` — 1바이트
- `WORD` — 2바이트
- `DWORD` — 4바이트
- `QWORD` — 8바이트

### 함수

프로시저, 서브루틴 이라고도 불린다.

| 명령어 | 동작 | 등가 코드 | rsp 변화 |
| --- | --- | --- | --- |
| `push val` | 스택에 값을 저장 | `sub rsp, 8` + `mov [rsp], val` | -8 |
| `pop reg` | 스택에서 값을 꺼냄 | `mov reg, [rsp]` + `add rsp, 8` | +8 |
| `call addr` | 반환 주소를 저장하고 함수로 점프 | `push rip` + `jmp addr` | -8 |
| `ret` | 반환 주소를 꺼내 복귀 | `pop rip` | +8 |
| `leave` | 스택 프레임 정리 | `mov rsp, rbp` + `pop rbp` | rbp+8로 복원 |

#### 함수의 호출 과정

```nasm
section .text
global _start

; ── 함수 정의 ──────────────────────────
my_add:
    push rbp        ; [프롤로그] caller의 rbp 백업
    mov  rbp, rsp   ;           현재 스택 최상단을 프레임 base로
    mov  rax, rdi   ; 1번 인자 → rax        (인자: rdi rsi rdx rcx r8 r9)
    add  rax, rsi   ; rax += 2번 인자        (반환값은 rax)
    pop  rbp        ; [에필로그] rbp 복원
    ret             ; pop rip → 반환 주소로 복귀

; ── 진입점 ─────────────────────────────
_start:
    mov  rdi, 10    ; 1번 인자
    mov  rsi, 20    ; 2번 인자
    call my_add     ; push 반환주소 + jmp  → rax = 30
    mov  rdi, rax   ; exit의 인자로 전달
    mov  rax, 60    ; syscall 번호 60 = exit
    syscall         ; exit(30)
```

### 시스템 콜

유저 모드에서 커널 모드의 시스템 소프트웨어에게 어떤 동작을 요청하기 위해 사용한다.

1. 시스템 콜 번호를 rax에 넣는다.
2. 인자를 정해진 레지스터에 순서대로 넣는다.
3. syscall 명령어를 실행한다.

```nasm
section .data
    filename db "dreamhack.txt", 0
section .bss
    buffer   resb 100

section .text
global _start
_start:
    ; fd = open("dreamhack.txt", O_RDONLY)
    mov rax, 2
    lea rdi, [filename]
    mov rsi, 0
    xor rdx, rdx
    syscall

    ; read(fd, buffer, 100)
    mov rdi, rax         ; open의 반환값(fd)이 read의 인자로
    mov rax, 0
    lea rsi, [buffer]
    mov rdx, 100
    syscall

    ; write(1, buffer, 읽은 바이트 수)
    mov rdx, rax         ; read의 반환값이 write의 인자로
    mov rax, 1
    mov rdi, 1
    lea rsi, [buffer]
    syscall

    ; exit(0)
    mov rax, 60
    xor rdi, rdi
    syscall
```

## 함수 호출 규약

Caller와 Callee가 서로 다른 파일에서 컴파일 될 수 있기 때문에 미리 정해놓는 규칙이다.

### x86 규약

32비트는 레지스터가 8개뿐이라 대부분 인자를 스택으로 넘긴다.

| 함수호출규약 | 사용 컴파일러 | 인자 전달 방식 | 스택 정리 | 적용 |
| --- | --- | --- | --- | --- |
| cdecl | GCC, MSVC | Stack | Caller | 일반 함수 |
| stdcall | MSVC | Stack | Callee | WINAPI |
| fastcall | MSVC | ECX, EDX | Callee | 최적화된 함수 |
| thiscall | MSVC | ECX(인스턴스),<br>Stack(인자) | Callee | 클래스의 함수 |

### x86-64 SYSV 규약

리눅스, macOS 64비트 표준으로 레지스터가 16개로 늘어난다.

| 함수호출규약 | 사용 컴파일러 | 인자 전달 방식 | 스택 정리 | 적용 |
| --- | --- | --- | --- | --- |
| System ABI | GCC | RDI, RSI, RDX,<br>RCX, R8, R9,<br>XMM0–7 | Caller | 일반 함수 |
| MS ABI | MSVC | RCX, RDX, R8, R9 | Caller | 일반 함수,<br>Windows Syscall |

**1. 인자 전달**

정수·포인터는 `rdi` → `rsi` → `rdx` → `rcx` → `r8` → `r9` 순서로 전달하고,
7번째부터는 스택에 오른쪽부터 push한다. 실수는 `xmm0` ~ `xmm7`을 사용한다.

**2. 반환 주소 저장**

`call`이 반환 주소를 스택에 자동 push 후 함수로 점프하므로,
함수 진입 시점의 `[rsp]`는 반환 주소가 된다.

**3. 스택 프레임 할당**

```nasm
push rbp        ; caller의 rbp 백업
mov  rbp, rsp   ; 새 프레임 base
sub  rsp, N     ; 지역변수 공간
```

지역변수는 `[rbp-8]`부터 아래로 배치된다.

**4. 반환**

```nasm
leave           ; mov rsp, rbp + pop rbp
ret             ; pop rip
```

> 반환값은 `rax`에 담아서 복귀한다.
